Part 1: Creating a Debugging Framework in PL/SQL 

Objective: 

Develop a modular debugging framework for PL/SQL, designed to monitor, trace, and diagnose errors and execution flows in medium and large-scale applications. 

 

Definition – What is a Debugging Framework in PL/SQL? 

A debugging framework is an organized set of: 

•	Controlled logging mechanisms 

•	Variable and status message capture 

•	Uniform exception handling 

•	Reusable structures for monitoring code execution 

It helps improve code quality, quickly identify issues, and simplify application maintenance. 

Essential Components 

1. Logging Table (debug_log) 

Stores debug records with details about the module, line number, and message generated during execution. 

CREATE TABLE debug_log ( 

  log_id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, 

  log_time TIMESTAMP DEFAULT SYSTIMESTAMP, 

  module_name VARCHAR2(100), 

  line_no NUMBER, 

  log_message VARCHAR2(4000), 

  session_id VARCHAR2(50) DEFAULT SYS_CONTEXT('USERENV', 'SESSIONID') 

); 

 

2. Utility Package: debug_utils 

A PL/SQL package providing procedures for logging and controlling debug mode: 

-- Enable/disable debug mode 

PROCEDURE enable_debug; 

PROCEDURE disable_debug; 

 

-- Log messages and variable values 

PROCEDURE log_msg(p_message VARCHAR2); 

PROCEDURE log_variable(p_name VARCHAR2, p_value VARCHAR2); 

PROCEDURE log_error(p_proc VARCHAR2, p_err VARCHAR2); 

 

Desired Features 

•	Dynamic enabling/disabling of debug mode 

•	Conditional logging based on global flag g_debug_mode 

•	Logging of module name, line number, and current session 

•	Ability to extend the framework with logging levels (INFO, WARN, ERROR) 

 

Use Cases 

This framework is useful for: 

•	Complex procedures containing branching logic or calculations 

•	Monitoring execution in test environments 

•	Debugging runtime exceptions 

•	Auditing execution in critical applications (e.g., financial, banking) 

 

Part 2: Using the Framework in Code 

Objective: 

Create a PL/SQL procedure that updates employee salaries based on the commission_pct value. 

Behavior: 

1.	For each employee: 

•	If commission_pct has a defined value (not NULL), the salary will be increased proportionally by that percentage. 

•	If commission_pct is NULL, the salary will be increased by 2% of the current value. 

2.	The procedure must use the debugging package (debug_util) so that: 

•	At each important step (reading data, calculation, update), a log message is recorded only if debug mode is active. 

Technical Objectives 

•	Write a procedure named, for example, adjust_salaries_by_commission. 

•	Integrate with a debug_util package containing: 

•	Control flag g_debug_mode 

•	Procedure log(p_module_name, p_line, p_message) 

•	Use dynamic SQL or an explicit cursor, depending on preference. 

•	Handle NULL commission_pct using NVL logic or IF statements. 

Optional: Logging Levels 

You may add log levels (DEBUG, INFO, WARN, ERROR) and flags to enable/disable them at runtime.
